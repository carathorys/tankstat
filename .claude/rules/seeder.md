# The Seeder

- **Seeder:** `src/backend/Tankstat.Seeder` (`mise run seed`) is a test-only standalone tool: it deletes, creates, migrates and seeds a database through the domain factories (so domain rules apply), creates no users, uses the no-auth owner, and refuses unless `Auth:Mode` is None, read as the app reads it (the environment over the settings file: `--settings`, `Settings:Path`). Keep it that way: no users, no auth modes. It asks for confirmation unless `--yes`. It also seeds recurring expenses (mixed states, so the app derives reminders), expenses (each schedule's visits, linked by `RecurringCompletion` as *Mark as done* links them, the last at its baseline; one-off ones, `--expenses`, within the fuel log's dates, or the last half year without a reading when there is no log; the vehicle's home currency) and access-change notifications for the anonymous user (made-up people, `DataGenerator.Notifications`); each part uses its own `Random` from the seed so adding one does not change the others (seed: vehicles and logs, +1 schedules, +2 notifications, +3 expenses). Every reading, an expense's or a schedule's baseline included, is placed by the vehicle's `OdometerTrajectory` (the log's readings, a straight line between them, the log's pace before it, a default pace for a log of one): a day's odometer (`At`), or for an odometer a distance limit gives, the last day the vehicle had not passed it (`DateAt`), so it fits between the readings of the days before and after it as `OdometerService` requires; no expense reading is later than the last fill-up, which stays the latest reading. A schedule's state is drawn and each limit it counts placed for it; one that counts both is last done at whichever came later, since the app goes by the one further along (`SeededExpensesTests` checks the states per kind). Pictures (`Pictures/`, opt-in: `--pictures` = a photo of the model from Wikimedia Commons, `--drawn-pictures` = `DrawnPicture`, a PNG drawn without an image library; both off by default, and the tests never touch the network: `CommonsPictures` takes an `HttpClient`, faked in `SeedPicturesTests`): `VehiclePictures` gives every vehicle, the trash's too, one after the seeding, stored as the app stores an upload (`IImageStore` into `ImageFolders.VehiclePicture`, a `StoredImage` row, `Vehicle.SetPicture`), from a `Random` per vehicle (`RandomFor`: FNV-1a of the seed and its name, never `string.GetHashCode`, which differs per process), so the same seed gives the same pictures; a model's Commons candidates (search order, JPEG/PNG thumbnails of 1280 px) and every photo are cached (`--pictures-cache`), so a seed again is offline and the same; a photo that cannot be had falls back to a drawn one. `--uploads` is also `Storage:Path` for the run, where the pictures go. New entities/rules: keep the generated data consistent (see `DataGenerator`) and its tests green.
