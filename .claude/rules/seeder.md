# The Seeder

- **Seeder:** `src/backend/Tankstat.Seeder` (`mise run seed`) is a test-only standalone tool: it deletes, creates, migrates and seeds a database through the domain factories (so domain rules apply), creates no users, uses the no-auth owner, and refuses unless `Auth:Mode` is None, read as the app reads it (the environment over the settings file: `--settings`, `Settings:Path`). Keep it that way: no users, no auth modes. It asks for confirmation unless `--yes`. It also seeds recurring expenses (mixed states, so the app derives reminders) and access-change notifications for the anonymous user (made-up people, `DataGenerator.Notifications`); each part uses its own `Random` from the seed so adding one does not change the others. Pictures (`Pictures/`, opt-in: `--pictures` = a photo of the model from Wikimedia Commons, `--drawn-pictures` = `DrawnPicture`, a PNG drawn without an image library; both off by default, and the tests never touch the network: `CommonsPictures` takes an `HttpClient`, faked in `SeedPicturesTests`): `VehiclePictures` gives every vehicle, the trash's too, one after the seeding, stored as the app stores an upload (`IImageStore` into `ImageFolders.VehiclePicture`, a `StoredImage` row, `Vehicle.SetPicture`), from a `Random` per vehicle (`RandomFor`: FNV-1a of the seed and its name, never `string.GetHashCode`, which differs per process), so the same seed gives the same pictures; a model's Commons candidates (search order, JPEG/PNG thumbnails of 1280 px) and every photo are cached (`--pictures-cache`), so a seed again is offline and the same; a photo that cannot be had falls back to a drawn one. `--uploads` is also `Storage:Path` for the run, where the pictures go. New entities/rules: keep the generated data consistent (see `DataGenerator`) and its tests green.
