# CI, and tests against appsettings.json

- **CI and tests vs. appsettings.json:** `.github/workflows/ci.yml` runs frontend (lint, types, `vite build` uploaded as `web-dist`), frontend tests (Vitest with coverage in 3 shards, `--shard=N/3` + `npm run coverage:paths`; `vitest.config.ts`, which holds the test settings on top of `vite.config.ts`, splits the files by the measured times in `tests/frontend/durations.json` (`DurationSequencer`; a file not measured counts by its size; `mise run test:durations` measures again)), backend (`scripts/test-backend.sh`: the test projects side by side, the integration tests in three processes by the first letter of the test class, each from its own copy of the build because coverage rewrites the assemblies in place; their `TestApp`s start from a database migrated once per run (`migrated: false` for a test about the migrations themselves)), smoke and codegen jobs in parallel (via mise; `node_modules` cached by `.github/actions/node-modules`), and a build job that only waits for the frontend job: it publishes the API once with `mise run build:api` (`VERSION` worked out once by the frontend job, which builds the web app with it too: the `version` input of `workflow_call`, else `0.0.0-dev.<sha>`) into `out/`, the artifact `tankstat-<sha>`; keep it in step with `mise run test`. The `e2e` job waits for the build, in two shards on two machines (`--shard=N/2`, each with its own server; `fullyParallel` lets Playwright split by test): it downloads that artifact into `out/` and runs `scripts/test-e2e.sh` with `E2E_NATIVE=1` (Chromium cached per Playwright version in `~/.cache/ms-playwright`, installed with its system libraries by `npx playwright install --with-deps chromium`), and on a failure uploads `test-results/e2e` (videos, traces, screenshots) and `playwright-report` as `e2e-results-N` (the layer itself: `.claude/rules/e2e.md`). Tests must never depend on the `Auth:Mode` (or admin settings) that `appsettings.json` happens to contain: every host/process started by a test sets the mode (and clears the bootstrap admin when it matters) itself; the smoke processes also drop `Recognition__`, `Storage__`, `Settings__` and `Backups__` variables from the developer's environment (the photos move at start would touch a developer's own folders; `scripts/test-api.sh` gives its server throwaway upload and backups folders and unsets `Backups__Every`/`Days`/`Keep`/`KeepDays`, `TestApp` gives every host `Setup:Enabled=false` (an empty database would wait for its setup: a notice more and a code line; the setup's own tests turn it on, and the template database is left with its setup undecided, `UndecideSetup`, so each copy decides afresh; `scripts/test-api.sh` sets `Setup__Enabled=false`, the smoke processes drop `Setup__` and leave it on) and a backups folder of its own and sets those three null over the environment only where the environment sets them, read as the configuration reads it (any spelling; a key a host holds in memory is read-only on the settings page, whose tests save them on a host of `BackupScheduleTests.AppWithSettingsFile`), and `ApiFixture` does the same with variables: a start writes a missed backup and retention prunes the folder). `Tankstat.Api.SmokeTests` start the real app as a process per mode; one test deliberately runs with only the shipped `appsettings.json`.
