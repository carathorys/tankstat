# CI, and tests against appsettings.json

- **CI and tests vs. appsettings.json:** `.github/workflows/ci.yml` runs on a push to `main` or a pull request only when it changes more than Markdown files (its `paths` filter: `**`, then `!**/*.md`, then back in `docs/photo-reading.md`, pinned by `OpenAiCompatiblePromptTests`, and `tests/**`; a new test that reads a Markdown file adds it there; `workflow_call` from the release has no filter); it runs frontend (lint, types, `vite build` uploaded as `web-dist`), frontend tests (Vitest with coverage in 3 shards, `--shard=N/3` + `npm run coverage:paths`; `vitest.config.ts`, which holds the test settings on top of `vite.config.ts`, splits the files by the measured times in `src/frontend/tankstat-react/tests/durations.json` (`DurationSequencer`; a file not measured counts by its size; `mise run test:durations` measures again)), backend (`scripts/test-backend.sh`: the test projects side by side, the integration tests in three processes by the first letter of the test class, each from its own copy of the build because coverage rewrites the assemblies in place; their `TestApp`s start from a database migrated once per run (`migrated: false` for a test about the migrations themselves)), smoke and codegen jobs in parallel (via mise; the frontend jobs run in `src/frontend/tankstat-react` (`defaults.run.working-directory`), its `node_modules` cached by `.github/actions/node-modules`), and a build job that only waits for the frontend job: it publishes the API once with `mise run build:api` (`VERSION` worked out once by the frontend job, which builds the web app with it too: the `version` input of `workflow_call`, else `0.0.0-dev.<sha>`) into `out/`, the artifact `tankstat-<sha>`; keep it in step with `mise run test`. The `e2e` job waits for the build, in two shards on two machines (`--shard=N/2`, each with its own servers: the shared one and the setup's six waiting ones; `fullyParallel` lets Playwright split by test): it downloads that artifact into `out/` and runs `scripts/test-e2e.sh` with `E2E_NATIVE=1` (Chromium cached per Playwright version in `~/.cache/ms-playwright`, installed with its system libraries by `npx playwright install --with-deps chromium`), and on a failure uploads `src/frontend/tankstat-react/test-results/e2e` (videos, traces, screenshots) and `src/frontend/tankstat-react/playwright-report` as `e2e-results-N` (the layer itself: `.claude/rules/e2e.md`). Tests must never depend on the `Auth:Mode` (or admin settings) that `appsettings.json` happens to contain: every host/process started by a test sets the mode itself (a Standalone one gets its administrator from the setup: `TestApp` copies a template database set up once through `SetupService.FinishAsync` (so does `SharedData`, unless `standalone: false` asks for the migrated template, with no user), `AppProcess.StartStandaloneAsync` finishes it with the code from the log); the smoke processes also drop `Recognition__`, `Storage__`, `Settings__` and `Backups__` variables from the developer's environment (the photos move at start would touch a developer's own folders; `scripts/test-api.sh` gives its server throwaway upload and backups folders and unsets `Backups__Every`/`Days`/`Keep`/`KeepDays`, `TestApp` gives every host `Setup:Enabled=false` (an empty database would wait for its setup: a notice more and a code line; the setup's own tests turn it on (a Standalone host without a connection string of its own and with it off starts from the set-up Standalone template, `CopyStandaloneDatabase`; `RemoveAdministrators` takes its administrators away for the reopened setup), and the template database is left with its setup undecided, `UndecideSetup`, so each copy decides afresh; `scripts/test-api.sh` sets `Setup__Enabled=false`, the smoke processes drop `Setup__` and leave it on) and a backups folder of its own and sets those three null over the environment only where the environment sets them, the retired `Auth__Standalone__AdminEmail`/`AdminPassword` too (`SetupService.RetiredSettings`: a start that finds them warns, which the tests of a start without a Warning would fail on), read as the configuration reads it (any spelling; a key a host holds in memory is read-only on the settings page, whose tests save them on a host of `BackupScheduleTests.AppWithSettingsFile`), and `ApiFixture` does the same with variables: a start writes a missed backup and retention prunes the folder). `Tankstat.Api.SmokeTests` start the real app as a process per mode; one test deliberately runs with only the shipped `appsettings.json`.
