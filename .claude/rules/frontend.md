# Frontend: UI structure, grids, bundle size, charts and libraries

- **UI structure:** `react-router` pages in `src/frontend/pages` (vehicle page tabs in `pages/vehicle`), shell (top bar, docked/overlay navigation, health footer: always the web app's version, `appVersion.ts` = `__APP_VERSION__` defined by `vite.config.ts` from the build's `VERSION` (CI's frontend job, the Dockerfile's frontend stage, checked by `docker-smoke.sh`), then the API's status and version while the server answers, else the connectivity message) in `src/frontend/shell`; shared bits: `forms/` (`Form`: native constraint validation with `noValidate`, on submit every Field refreshes its custom validity, `checkValidity()` shows the messages and the first invalid control takes the focus; `refusal` (the form's last submit error) said at the field it is about (`forms/refusals.ts` `FIELD_OF_KEY`: a server's `*Required` key to the form's field name), which takes the focus, while an `ErrorMessage` of the same error inside the form says nothing, so every required value is said at its field, the form's own check or the server's; `Field`: label above, hint, `extra` and error messages linked by `aria-describedby` (its own check first, then `refusal`, the server's word on the value sent); `FieldInput`, `FieldDate` (MUI X picker, lazy `DatePickerImpl`, hidden ISO input, `disableFuture`), `FieldAutocomplete`, `CurrencyInput` (ISO codes with `Intl` names), `PasswordInput` for every password, passphrase or secret (#120: a real `type="password"` input with the caller's `autoComplete`, a Show button of its own per field (`aria-pressed`, `aria-controls`, `showLabel` saying what it shows) that is never on at first and hides again after `REVEAL_IDLE_MS` (30 s) without a keystroke, on leaving the field and its button, on its form's submit (also one the checks stop) and on unmount; the button's `mousedown` keeps the focus in the input; Edge's own reveal hidden; a Caps Lock note in the field's description inside a `role="status"`), `NewPasswordFields` for a new password and its repetition `<name>Repeat` (each a `PasswordInput`, `autocomplete="new-password"`; the new one says the minimum before typing (`forms.password.requirements`, from the public `PasswordRequirements` query, `keep` offline, `PASSWORD_FLOOR` 10 without an answer) and a shorter one is its own `invalid` (`errors.password.tooShort`), as is a password longer than the query's `maxLength` (`errors.password.tooLong`; no native `maxlength`, which would cut a paste short without a word); a different repetition is the field's own `invalid`, `errors.password.mismatch`, so the form stops the submit and focuses it), `FieldForm` for plain text forms, `type: 'password'` rendering a `PasswordInput`, `type: 'newPassword'` the pair with `repeatLabel`; `PasswordForms.tsx`: `ChangePasswordForm` (`required` for the gate: no heading of its own, `Session` refetched, a toast) and `PasswordChangeRequiredView`, which `App.tsx` shows in place of every page, without the menu (`showMenu`), while `session.user.passwordChangeRequired`), `dialogs/` (`DialogFrame` + `DialogButtons` + `DialogCancel`, `useDialogState` (own or controlled `open`), `DialogTrigger`, `onClosed` after the exit; `busy` blocks Escape and backdrop), `toast/` (`useToast`: `toast('Saved.')` after a save, `undoable(message, undo)` with Undo for 10 s after trashing a vehicle, refuelling or expense; the confirmation before trashing stays), `messages.tsx` (error/success alerts) and `components/` (`ConfirmDialog`, `ImagePicker`, `UserAvatar`, `VehiclePicture`, `OdometerField`, `LabeledSelect`/`InlineSelect`, `LabeledSwitch`, `IconAction` (icon button + tooltip + aria-label from one label), `TabbedPanels` (a panel per tab, only the open one filled), `Segmented` (real radios), `DefinitionList`, `SurfaceTable`). The sidebar is docked and open by default on desktop (`tankstat.nav.open` in localStorage is the device's copy, the account's value comes through `UiSettingsProvider`, see Settings), an overlay on phones (never remembered). Pictures: resize in the browser (`pictures/resizeImage.ts`), upload raw with `pictures/upload.ts`; `ImagePicker` sends at once; only a vehicle's picture (`keep`) can wait on the device (see A vehicle's picture offline), anything else keeps nothing for later, so it is off while the server is out of reach (`image.needsServer` as its description) and shows a lost connection as the calm `OfflineError` note. Look (`theme/`): dim dark sand/indigo palette copied once from Radix Colors (`scales.ts`), floating panels drawn by `glass(theme)` in `components.ts` (top bar, drawer, dialogs, menus, popovers, cards, `SurfaceTable`, the toasts; never a see-through background of their own) as the user chose (**Surfaces**: Glossy = translucent and blurred, the default; Transparent = translucent, no blur; Opaque = solid paper of the panel's own scheme): `glass` reads `--tk-glass-alpha` (0.7 dark, 0.85 light, merged into the shadow tokens' `:root, .dark`/`.light` rules) and `--tk-glass-filter`, and a class on `<html>` (`surface-transparent`/`surface-opaque`, `theme/surface.ts` `SURFACE_CLASS`; glossy has none) switches them (`SURFACE_TOKENS`, which also hold the home card figures' `--tk-scrim`/`--tk-scrim-filter`); `theme/surfaceStore.ts` (`setSurface`, `useSurface`) sets the class and the browser's copy (`tankstat.surface`), the account keeps `UiSettings.Surface` (`UiSettingsProvider.setSurface`); a toast is `glass` with its severity's `soft` tint over it, text in `text.primary`, the icon in `softText`, a hairline in the severity's colour and `shadows[9]`, soft shadows (`--tk-shadow-n` variables), pill controls, soft/ghost button and chip variants, system fonts; light and dark schemes as CSS variables (class on `<html>`, `ThemeProvider` with `modeStorageKey`). **Colour mode** (Light/Dark/System, default Dark): `shell/AppearanceMenu.tsx` next to the language menu (one menu, two groups: colour mode and surfaces; `RadioMenu` `groups`: a separator between them, a heading only seen, items named "<group>: <choice>" except a language's own name, which carries its `lang` and says itself, all the menu's own children), MUI's `useColorScheme`, the browser keeps it under `tankstat.colorMode`, the account under `UiSettings.ColorMode` (`UiSettingsProvider.setColorMode`; see Settings); `theme/initScheme.ts` is put into `index.html` by a Vite plugin (`vite.config.ts`) and sets the class, the colour scheme, `theme-color` and the surface class before the first paint (it must stay free of imports other than `colorMode.ts`, `scales.ts` and `surface.ts`, which import nothing and touch no page, since Vite loads them in Node; the store is `surfaceStore.ts`). Vehicle cards and the banner always have white text on a dark scrim, so they carry the `dark` class. Dialogs are uncontrolled where possible: `DialogTrigger` clones the caller's button, no open-state in the page; pass `open`/`onOpenChange` only when something else opens it (a menu, the floating add button, a home card's Done button). Tests render with `renderWithApollo(ui, route)` (MemoryRouter) and the in-memory `fakeVehicleBackend` from `tests/frontend/support/mocks.tsx`; the footer's status badge also has `role="status"`, so query status messages by text.

- **Grids:** sorting/paging/column selection are server-side only (`VehicleQuery`/`RefuelingQuery`: orderBy/direction/skip/take; count queries for paging). `grid/ServerGrid` runs on MUI X's Data Grid in server mode (`sortingMode`/`paginationMode="server"`; the first visible column is the `rowHeader`; `autoHeight` + `disableVirtualization` + auto row height, so it holds at most 100 rows; no column menu, filter or resizing; the footer's texts come from our i18n, `huHU` for the rest). A row being trashed fades (`useLeavingRows`, `.tk-leaving`) while the server removes it. `ServerGrid` + `useGridSettings` (own state types, no table library) (localStorage `tankstat.grid.<id>` is the device's copy, the account's through `UiSettingsProvider` when one is mounted; `merge` validates against current columns) are generic; add a column by adding a `GridColumn` (and the `@include` variable); `defaultHidden: true` hides a column on every screen until the user shows it (a saved choice wins), while `mobile: false` hides it on phones only. Repositories always end the order with the id so pages are stable. A field resolved per row of a list (a log's `canEdit`/`canDelete`, `createdBy`, `vehicle`) goes through a batch data loader (`Api/GraphQL/LogRowLoaders.cs`, `AccessService.LogLevelsAsync`), never a query of its own: HotChocolate resolves rows in parallel, so a page of 100 rows asked one by one opened hundreds of connections at once and failed on PostgreSQL (`LogListQueriesTests` counts the contexts a page uses). Queries use `cache-and-network` so every visit refetches.

- **Touch targets:** on a touch screen (`COARSE`, `(pointer: coarse)` in `theme/components.ts`) every control is at least 44 px; the theme gives it to buttons, icon buttons, menu items, fields, checkboxes and radios. A text link counts too unless it is inline in a sentence (WCAG 2.5.8's exception; its parent has text of its own, as the Overview's "Go to Server settings"): a link on its own (a value in a `DefinitionList`, a name in a grid, a "Change the settings" line under a panel, a `Link component="button"`) spreads `standaloneLink` last in its `sx` (inline-flex, 44 px tall on a coarse pointer only; after the link's own `minHeight`, which would win otherwise). A link that flows after inline content (a notification behind its "New" chip) takes vertical padding instead (`NotificationItem`), which moves nothing, as long as no other target is within 44 px. The top bar's name keeps its block for the ellipsis and gets a 44 px line height. A stretched link (an absolutely positioned `::after` over its container, the home card's title) counts by its container. jsdom lays nothing out: sizes are measured in a real browser.
- **Bundle size:** every page in `App.tsx` is `React.lazy` (its own chunk), the dashboard and the two log tabs (the data grid) are lazy inside the vehicle page, sparklines through `LazySparkline` and the schedule dials through `LazyGauges`, the date picker inside `FieldDate`, so MUI X Charts (~145 kB), the Data Grid (~425 kB) and the pickers (~170 kB) only load when shown (the service worker precaches those chunks in the background after the first visit, see PWA); the entry chunk is the shell, MUI core, Apollo, i18n and the offline link (~470 kB, 149 kB gzipped; Emotion injects the styles, so the build has no stylesheet). Keep new pages lazy, and do not import `dashboard/*` (except `chartFormat.ts`) or `@mui/x-*` from eagerly loaded code. In tests lazy content appears asynchronously: use `findBy*`.
- **Charts:** MUI X Charts, always inside `ChartView` (bars, lines, areas, donuts; the picture is `aria-hidden`, `disableKeyboardNavigation`, `skipAnimation` under reduced motion; the same data is a table behind a toggle: keep it that way for accessibility, tests read the table because jsdom cannot lay out SVG); series colours are `SERIES_COLORS` (`theme/scales.ts`). The Recurring tab shows a dial per limit (`recurringProgress.ts`, pure, + `dashboard/ProgressGauges.tsx`: a combined schedule has two, the deciding one at full strength; a picture only, the state badge and due text say the same). Vehicle pictures are drawn by `CoverLayers` (the picture as a CSS `background-image` with `cover` sizing, so it is cropped and never stretched, plus a dark scrim) behind white text on cards and the vehicle banner.
- **Frontend libraries:** MUI + MUI X (see API), icons from `lucide-react`, animations: short (about 0.2 s), and only for a change of state, never decoration; `MotionConfig reducedMotion="user"` (main.tsx) keeps only fades under reduced motion. Something that only comes in uses the CSS classes of the theme (`MOTION_CLASSES` in `theme/components.ts`: `tk-appear`, `tk-fade` for a swapped value such as a badge with `key={state}`, `tk-delayed` for a wait indicator, `tk-pulse` for work in progress, `tk-spin`; all off under `prefers-reduced-motion`). Something that leaves or moves uses `motion/react` with the presets in `components/motion.ts` (`MotionTableRow` + `rowMotion` for table rows, `itemMotion` with `layout` for list items; a grid's rows use `useLeavingRows` instead) inside `AnimatePresence initial={false}`. Exception: a home card's attention rows leave at once, because the card moves the focus to its title only once the clicked Done button is gone. Waiting: skeletons (home cards, dashboard, chart cards: a hidden `role="status"` says "Loading…"), `components/Loading.tsx` (spinner + text, `role="status"`) for a page's Suspense, Save buttons `loading={busy}` and `SaveWait` while photos upload, `recognition/ReadingProgress.tsx` in the reading status region ("you can save now", with a bar of the wait that has passed), and a short "Saved." toast after a save. Tests set `MotionGlobalConfig.skipAnimations` (`tests/frontend/support/setup.ts`), so a leaving item is gone at once. Build mobile-first and check desktop too.
