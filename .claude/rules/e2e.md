# Real-browser tests (Playwright)

- **Required for every user flow:** a new user flow (something a person does across pages or dialogs: a new feature, or a new way through an existing one) gets a Playwright test here in the same change, running at both sizes; a changed flow updates its test; `mise run test:e2e` runs before that commit. A page whose layout changes gets a layout test too. The file of the flow's area holds it (below), a new area gets a file of its own.

- **The layer:** `src/frontend/tankstat-react/e2e/*.e2e.ts`, `@playwright/test` (pinned exactly, no `^`: the Docker image's tag is its version), Chromium only, two projects in `playwright.config.ts`: `phone` (`devices['Pixel 7']`: 412 px, touch, `(pointer: coarse)`) and `desktop` (1280 × 900), both dark and `en-US`. No pixel snapshots: the tests assert layout rules and what the page shows. `mise run test:e2e` builds `out/` and runs `scripts/test-e2e.sh`; it is **not** part of `mise run test`. Typechecked by `tsconfig.e2e.json` (in `tsconfig.json`'s references, so `npm run typecheck` covers it); Vitest never picks the files up.
- **The app is the published build:** `scripts/test-e2e.sh` starts `out/Tankstat.Api.dll` **from `out/`** (the content root, and with it `wwwroot`, is the working directory; started elsewhere `/` is 404) on port 5097 (`E2E_PORT`), Production, Standalone, throwaway database, upload, photos, backups and keys folders and settings file; its setup (the only way to a first administrator, #149) is finished by the script once the API answers, the unattended way: the code from its log and one `setupFinish` (the code read by `setup_code`, which waits for the line; `/graphql` needs no `X-Requested-With`, only `/auth/token/*` does) making `root@example.com` / `initial-password-1` (`src/frontend/tankstat-react/e2e/support/app.ts` `ADMIN`), which must answer `"restarting":false`. Next to it, on the next six ports, six instances that wait for their setup, for `setup.e2e.ts`: one per setup test and size (`phone-fresh`, `desktop-fresh`, `phone-restore`, `desktop-restore`, `phone-reopened`, `desktop-reopened`), since finishing a setup or restoring into it cannot be undone; folders of their own and nothing else set, so the fresh ones run the shipped sign-in off (the wizard chooses the mode), the restore ones `Auth__Mode=Standalone` without an administrator, plus the shared server's `instance_env` (the OIDC values, the administrator list, the backup time): a backup records the settings its server's environment holds, and a restore where one has no value is refused (#140), so a move with the same compose file is what they stand for; the reopened ones are started once with `Auth__Mode=None Setup__Enabled=false` (set up by the environment), stopped once their API answers (that first start is the subshell's own child, which its EXIT/TERM traps stop when it ends early: the script's cleanup reaches only the subshells), and started again in `Standalone` on the same port, so their setup reopens; the script waits for each waiting server's code line first (`setup_code`, polling the log), then for its API, since a reopened server's first start answers on that port without a code. Their addresses and one-time codes (from the code line each start logs) reach the tests as `E2E_SETUP` (JSON by name, also passed into the Docker run; `support/setup.ts` `waitingServer(kind)` picks the test's own by its project). It first drops the developer's `Auth__`, `Database__`, `Storage__`, `Settings__`, `Backups__`, `Recognition__`, `DataProtection__`, `Setup__`, `Smtp__`, `Defaults__`, `Notifications__`, `Sync__`, `Logging__`, `Kestrel__`, `ASPNETCORE_`, `OTEL_` and `Telemetry__` variables, in any case (.NET reads them so). The OIDC values, `Auth__AdminEmails__0` and a backup time on no day (`Backups__Days=None`, nothing scheduled) are set (`instance_env`) so the Server settings page has read-only rows. It waits for every server's API, runs the tests, prints the app's (and each waiting server's) last log lines on a failure, and always stops them and removes the folders. Arguments go to `playwright test` (`mise run test:e2e -- --project phone -g Backups`).
- **Where Playwright runs:** natively with `E2E_NATIVE=1` (CI: `npx playwright install --with-deps chromium`); otherwise in `mcr.microsoft.com/playwright:v<installed version>-noble` (this machine's Linux is not a Playwright host) with `--network host --ipc=host`, **as the host user** (`--user $(id -u):$(id -g) -e HOME=/tmp`, or root-owned files are left behind), the repository mounted at its own path, `-w` the web app's folder (`src/frontend/tankstat-react`: its config and `node_modules`) (plain JavaScript; the image brings the browsers). Moving `@playwright/test` moves the image: a mismatch fails at launch.
- **Output:** Playwright runs from `src/frontend/tankstat-react`, so its paths are from there (a file a test uploads: `e2e/files/...`, a backend contract file: `../../../tests/backend/contracts/...`). `outputDir` is `test-results/e2e` (Playwright empties it at every start; `test-results/` itself holds other tools' output), a trace, a screenshot and a video (`video.webm`, `retain-on-failure`: recorded for every test, kept only for a failed one) on failure only; the HTML report in `playwright-report/` (ignored), never opened by itself. `npx playwright show-report`; `npx playwright show-trace test-results/e2e/<test>/trace.zip`.
- **Data:** one server for the whole run and parallel workers, so every test makes what it needs through GraphQL (`support/app.ts`: `signIn` through `page.request`, which shares the context's cookies, or a request context of its own; `graphql`, which fails on an error (a page or a request context); `addVehicle` (either too), `logRefueling`, `addExpense`, `addDueRecurring`; `picture` draws a PNG in the page for an upload) and never asserts a count or relies on another test's data. **A flow runs as a user of its own** (`createUser` / `signInAsNewUser`: made by the administrator, the password set through the reset token `createUser` answers, since setting one directly is off by default), so its home page, trash, notifications, language, colour mode, grid columns and a failed sign-in's lockout are its alone; only what needs the administrator signs in as `ADMIN`. A second person or device is a context of its own (`newContext(browser)` from `support/test.ts`, never `browser.newContext()` itself, closed in `finally`). What is shared by the whole server (a server setting) is changed by each size on a setting of its own, to a random value, and checked by its source, so runs side by side and repeats never collide; never anything that restarts the shared server (a restore, a mode change); the setup's tests restart only their own waiting servers. One exception, set once: the global setup (`support/global-setup.ts`, `globalSetup` in `playwright.config.ts`, per CI shard against its own server) makes a user per project with a 10-character password, then raises `Auth:Standalone:PasswordMinLength` to `RAISED_MINIMUM` (14) for the whole run (a raise inside a test would race every other test's user made meanwhile); the users reach the tests as `E2E_SHORT_PASSWORDS` (JSON by project name) for the change asked at the next sign-in (`account.e2e.ts`). Every other password the tests use (`createUser`'s, `ADMIN`'s, the setup's) must stay longer than that minimum, and the minimum at most 17: the shared server's backup carries it to the setup's restore servers, where `ADMIN` signs in. `getByRole(dialog)` does not match a confirmation (`role="alertdialog"`). A dashboard set through GraphQL (`dashboard.e2e.ts` `arrange`, `axe.e2e.ts`) sends `layoutVersion: LAYOUT_VERSION` (`support/app.ts`, the web app's value in `src/dashboard/widgets.ts`, raised with it): without it the server refuses the save (`dashboard.updateApp`, #273). `src/frontend/tankstat-react/e2e/files/` holds the upload fixtures (a Fuelio export). No Seeder. **No service worker** (#236): every file imports `test`/`expect` from `support/test.ts`, whose `context` (and `newContext(browser)` for a second person or device) deletes `navigator.serviceWorker` before the app loads (`screenshots.ts` takes its `test` from there too), so the "can now be used offline" toast never lands over the control a phone test taps at the bottom of the screen; only `offline.e2e.ts` imports `@playwright/test` itself, since offline its dialogs' lazy chunks come from the worker's cache (`serviceWorkers: 'block'` broke it for that reason). A list that pages finds the test's own item by searching for it (the home page lists one page of vehicles by name, which the other tests' vehicles fill).
- **Waits are on what the page shows:** the `h1` and no loading message (`pageLoaded`), the selected tab, `MuiCollapse-entered`, `expect.poll`. Never `waitForLoadState('networkidle')` (two settings tabs never reach it) and never a fixed timeout. `retries: 0`: a flaky test is fixed. `fullyParallel`: the tests of a file run side by side too, so no test may depend on another's order or state. Wait for what a save answers (its toast, the dialog gone), never for a button turning off: it is off while the save runs too. Click inside the page (`evaluate(el => el.click())`) where a broken layout could cover the target, so the test fails with its layout lines rather than a timeout. `page.mouse` never scrolls: a drag or a resize by the pointer (`dashboard.e2e.ts`) works on what the first screen shows, and a mouse-down past the viewport lands on nothing (it selected text instead of dragging). Nor may its path come within 50 px of the screen's edge: react-grid-layout scrolls the page there (`EDGE_THRESHOLD`), away from a pointer that stays put; `followsThePointer` scrolls the part to the middle of the screen first (#240's CI failure: CI's fonts put the handle at 866 of 900 px). A drag reads a box and presses there, so it runs with nothing moving (#236): `dashboard.e2e.ts` runs under `reducedMotion: 'reduce'` (the grid's transitions off) and waits for `settled(locator)` (`support/app.ts`: the box the same two frames running, polled) before reading a box to drag from or to. An enabled MUI menu item has no `aria-disabled` at all (`not.toHaveAttribute('aria-disabled', 'true')`), a disabled one `"true"`.
- **The layout check** (`support/layout.ts`, `layoutProblems` / `expectSoundLayout`, which polls until it holds): the document no wider than the viewport; no `dd` value past its panel; no help button over its value; no dialog whose frame (`.MuiDialog-paper`) scrolls as a whole, down or sideways, only its content (#249: an absolutely positioned hidden input laid out against the frame stretched it; a popover's paper is its own scroll container and is not checked); on a coarse pointer every button, `role=button`, `role=tab` and icon link 44 × 44 and every text link 44 px tall (frontend rules, "Touch targets"), with half a pixel of slack (the phone's 2.625 device pixels per CSS pixel), except a link inline in a sentence (its parent has text of its own) and whatever is out of sight (the skip link); a stretched link counts by the box its `::after` covers. It returns readable lines (`"OIDC client id": value ends 235px past its panel`, `touch target 75x26: Tankstat`, `dialog "Add widget": its frame scrolls 998/868`, `... its frame scrolls sideways 480/450`). Measure before a full-page screenshot: under phone emulation it drops the touch emulation.
