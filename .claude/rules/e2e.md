# Real-browser tests (Playwright)

- **Required for every user flow:** a new user flow (something a person does across pages or dialogs: a new feature, or a new way through an existing one) gets a Playwright test here in the same change, running at both sizes; a changed flow updates its test; `mise run test:e2e` runs before that commit. A page whose layout changes gets a layout test too. The file of the flow's area holds it (below), a new area gets a file of its own.

- **The layer:** `tests/e2e/*.e2e.ts`, `@playwright/test` (pinned exactly, no `^`: the Docker image's tag is its version), Chromium only, two projects in `playwright.config.ts`: `phone` (`devices['Pixel 7']`: 412 px, touch, `(pointer: coarse)`) and `desktop` (1280 × 900), both dark and `en-US`. No pixel snapshots: the tests assert layout rules and what the page shows. `mise run test:e2e` builds `out/` and runs `scripts/test-e2e.sh`; it is **not** part of `mise run test`. Typechecked by `tsconfig.e2e.json` (in `tsconfig.json`'s references, so `npm run typecheck` covers it); Vitest never picks the files up.
- **The app is the published build:** `scripts/test-e2e.sh` starts `out/Tankstat.Api.dll` **from `out/`** (the content root, and with it `wwwroot`, is the working directory; started elsewhere `/` is 404) on port 5097 (`E2E_PORT`), Production, Standalone with the bootstrap administrator `root@example.com` / `initial-password-1` (`tests/e2e/support/app.ts` `ADMIN`), `Setup__Enabled=false`, throwaway database, upload, photos, backups and keys folders and settings file. Next to it, on the next four ports, four new instances that wait for their setup, for `setup.e2e.ts`: one per setup test and size (`phone-fresh`, `desktop-fresh`, `phone-restore`, `desktop-restore`), since finishing a setup or restoring into it cannot be undone; folders of their own and nothing else set, so the fresh ones run the shipped sign-in off (the wizard chooses the mode) and the restore ones `Auth__Mode=Standalone` without an administrator, plus the shared server's `instance_env` (the OIDC values, the administrator list, the backup time): a backup records the settings its server's environment holds, and a restore where one has no value is refused (#140), so a move with the same compose file is what they stand for. Their addresses and one-time codes (from the code line each start logs) reach the tests as `E2E_SETUP` (JSON by name, also passed into the Docker run; `support/setup.ts` `waitingServer(kind)` picks the test's own by its project). It first drops the developer's `Auth__`, `Database__`, `Storage__`, `Settings__`, `Backups__`, `Recognition__`, `DataProtection__`, `Setup__`, `Smtp__` and `ASPNETCORE_` variables. The OIDC values, `Auth__AdminEmails__0` and a backup time on no day (`Backups__Days=None`, nothing scheduled) are set (`instance_env`) so the Server settings page has read-only rows. It waits for every server's API, runs the tests, prints the app's (and each waiting server's) last log lines on a failure, and always stops them and removes the folders. Arguments go to `playwright test` (`mise run test:e2e -- --project phone -g Backups`).
- **Where Playwright runs:** natively with `E2E_NATIVE=1` (CI: `npx playwright install --with-deps chromium`); otherwise in `mcr.microsoft.com/playwright:v<installed version>-noble` (this machine's Linux is not a Playwright host) with `--network host --ipc=host`, **as the host user** (`--user $(id -u):$(id -g) -e HOME=/tmp`, or root-owned files are left behind), the repository mounted at its own path and its own `node_modules` (plain JavaScript; the image brings the browsers). Moving `@playwright/test` moves the image: a mismatch fails at launch.
- **Output:** `outputDir` is `test-results/e2e` (Playwright empties it at every start; `test-results/` itself holds other tools' output), a trace, a screenshot and a video (`video.webm`, `retain-on-failure`: recorded for every test, kept only for a failed one) on failure only; the HTML report in `playwright-report/` (ignored), never opened by itself. `npx playwright show-report`; `npx playwright show-trace test-results/e2e/<test>/trace.zip`.
- **Data:** one server for the whole run and parallel workers, so every test makes what it needs through GraphQL (`support/app.ts`: `signIn` through `page.request`, which shares the context's cookies, or a request context of its own; `graphql`, which fails on an error (a page or a request context); `addVehicle` (either too), `logRefueling`, `addExpense`, `addDueRecurring`; `picture` draws a PNG in the page for an upload) and never asserts a count or relies on another test's data. **A flow runs as a user of its own** (`createUser` / `signInAsNewUser`: made by the administrator, the password set through the reset token `createUser` answers, since setting one directly is off by default), so its home page, trash, notifications, language, colour mode, grid columns and a failed sign-in's lockout are its alone; only what needs the administrator signs in as `ADMIN`. A second person or device is a context of its own (`browser.newContext()`, closed in `finally`). What is shared by the whole server (a server setting) is changed by each size on a setting of its own, to a random value, and checked by its source, so runs side by side and repeats never collide; never anything that restarts the shared server (a restore, a mode change); the setup's tests restart only their own waiting servers. One exception, set once: the global setup (`support/global-setup.ts`, `globalSetup` in `playwright.config.ts`, per CI shard against its own server) makes a user per project with a 10-character password, then raises `Auth:Standalone:PasswordMinLength` to `RAISED_MINIMUM` (14) for the whole run (a raise inside a test would race every other test's user made meanwhile); the users reach the tests as `E2E_SHORT_PASSWORDS` (JSON by project name) for the change asked at the next sign-in (`account.e2e.ts`). Every other password the tests use (`createUser`'s, `ADMIN`'s, the setup's) must stay longer than that minimum, and the minimum at most 17: the shared server's backup carries it to the setup's restore servers, where `ADMIN` signs in. `getByRole(dialog)` does not match a confirmation (`role="alertdialog"`). `tests/e2e/files/` holds the upload fixtures (a Fuelio export). No Seeder. A list that pages finds the test's own item by searching for it (the home page lists one page of vehicles by name, which the other tests' vehicles fill).
- **Waits are on what the page shows:** the `h1` and no loading message (`pageLoaded`), the selected tab, `MuiCollapse-entered`, `expect.poll`. Never `waitForLoadState('networkidle')` (two settings tabs never reach it) and never a fixed timeout. `retries: 0`: a flaky test is fixed. `fullyParallel`: the tests of a file run side by side too, so no test may depend on another's order or state. Wait for what a save answers (its toast, the dialog gone), never for a button turning off: it is off while the save runs too. Click inside the page (`evaluate(el => el.click())`) where a broken layout could cover the target, so the test fails with its layout lines rather than a timeout.
- **The layout check** (`support/layout.ts`, `layoutProblems` / `expectSoundLayout`, which polls until it holds): the document no wider than the viewport; no `dd` value past its panel; no help button over its value; on a coarse pointer every button, `role=button`, `role=tab` and icon link 44 × 44 and every text link 44 px tall (frontend rules, "Touch targets"), with half a pixel of slack (the phone's 2.625 device pixels per CSS pixel), except a link inline in a sentence (its parent has text of its own) and whatever is out of sight (the skip link); a stretched link counts by the box its `::after` covers. It returns readable lines (`"OIDC client id": value ends 235px past its panel`, `touch target 75x26: Tankstat`). Measure before a full-page screenshot: under phone emulation it drops the touch emulation.
- **What runs:** `pages.e2e.ts` (Home with a vehicle card, Overview, Backups, Account, People) and `settings.e2e.ts` (every tab of the Server settings page by its `?tab=` name, which must be the selected tab, since the page falls back to the first one, every section open), `axe.e2e.ts` (`@axe-core/playwright` through `support/axe.ts` `violations`, pinned to the `axe-core` the jsdom scans use: Home, Overview, Server settings, Backups, Account, People, a vehicle's Refuelings tab, and the add vehicle and add refuelling dialogs scanned on their own (`include('[role="dialog"]')`); the jsdom scans stay, these add the colour contrast of the real styles), and `flows.e2e.ts` (signing in with the form; adding a vehicle and a refuelling through the dialogs, on a phone with the card's two taps, "Tap again to open"; writing a backup from the Backups page and downloading it; a key set made there, a typed passphrase stopped by its repetition, a made-up one typed back before *Use these keys* is enabled and left unused (the shared server's backups stay in plain for the setup's restores), its dialog checked by layout and axe; then its restore dialog naming what the server's environment set, nothing missing, scanned by axe, and cancelled; an older release's backup uploaded on the Backups page says its risk in its row, and its restore waits for the acknowledgement, then is cancelled; a backup written there held (no Delete then), opened with its tables and scanned by axe, and released again), and the user flows by area, each at both sizes: `logs.e2e.ts` (editing a refuelling, trashing one with Undo and restoring one from the trash, an expense added, edited and trashed, a recurring expense added and marked as done, Refuel/Expense/Done from the home card, the dashboard's key figures), `vehicles.e2e.ts` (editing, a picture, trash/restore/empty trash, the home search, Arrange), `account.e2e.ts` (a wrong password, signing out, changing the password, the change asked at sign-in for a password shorter than the minimum (the gate's layout and axe too), signing another device out, Hungarian kept with the account, the light colour mode, a profile picture, the forgotten password form), `admin.e2e.ts` (a new user through their one-time link, the same user created twice at once, disabling a user, a grant on someone else's data, the list of every vehicle), `sharing.e2e.ts` (a vehicle's logs shared, the other person logging a refuelling and the access removed; a due reminder read through the bell), `import.e2e.ts` (a Fuelio export into a new vehicle), `offline.e2e.ts` (a refuelling kept on the device while offline, `context.setOffline`, and sent when back; in-app navigation only while offline), `screens.e2e.ts` (a saved chart, a grid column hidden and kept, a server setting saved), `setup.e2e.ts` (each on its waiting server: the code, the wizard with the sign-in mode chosen (*Choose one to go on.* at its field first), on to the last step by its label, the first administrator, the restart into local accounts and the sign-in it asks for, the done screen; a backup of the shared server holding a vehicle made for it, uploaded on the setup page with a file chooser, its restore dialog naming the old server's environment with nothing missing (the restore servers set the same), restored, the restart, the restored administrator's sign-in and the vehicle back, and a notification setting each size saved on the shared server before its backup shown on the restored server's Server settings page (the settings file comes back with the backup); the layout check and axe on the code, the start, a settings step and the restore list, the layout check on the last step and the done screen). A new page or a page that changed gets its test here.
- **CI:** the `e2e` job in `ci.yml` (`.claude/rules/ci-and-tests.md`).
