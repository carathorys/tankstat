# Real-browser tests (Playwright)

- **The layer:** `tests/e2e/*.e2e.ts`, `@playwright/test` (pinned exactly, no `^`: the Docker image's tag is its version), Chromium only, two projects in `playwright.config.ts`: `phone` (`devices['Pixel 7']`: 412 px, touch, `(pointer: coarse)`) and `desktop` (1280 × 900), both dark and `en-US`. No pixel snapshots: the tests assert layout rules and what the page shows. `mise run test:e2e` builds `out/` and runs `scripts/test-e2e.sh`; it is **not** part of `mise run test`. Typechecked by `tsconfig.e2e.json` (in `tsconfig.json`'s references, so `npm run typecheck` covers it); Vitest never picks the files up.
- **The app is the published build:** `scripts/test-e2e.sh` starts `out/Tankstat.Api.dll` **from `out/`** (the content root, and with it `wwwroot`, is the working directory; started elsewhere `/` is 404) on port 5097 (`E2E_PORT`), Production, Standalone with the bootstrap administrator `root@example.com` / `initial-password-1` (`tests/e2e/support/app.ts` `ADMIN`), `Setup__Enabled=false`, throwaway database, upload, photos, backups and keys folders and settings file. It first drops the developer's `Auth__`, `Database__`, `Storage__`, `Settings__`, `Backups__`, `Recognition__`, `DataProtection__`, `Setup__`, `Smtp__` and `ASPNETCORE_` variables. The OIDC values, `Auth__AdminEmails__0` and a backup time on no day (`Backups__Days=None`, nothing scheduled) are set so the Server settings page has read-only rows. It waits for the API, runs the tests, prints the app's last log lines on a failure, and always stops the app and removes the folders. Arguments go to `playwright test` (`mise run test:e2e -- --project phone -g Backups`).
- **Where Playwright runs:** natively with `E2E_NATIVE=1` (CI: `npx playwright install --with-deps chromium`); otherwise in `mcr.microsoft.com/playwright:v<installed version>-noble` (this machine's Linux is not a Playwright host) with `--network host --ipc=host`, **as the host user** (`--user $(id -u):$(id -g) -e HOME=/tmp`, or root-owned files are left behind), the repository mounted at its own path and its own `node_modules` (plain JavaScript; the image brings the browsers). Moving `@playwright/test` moves the image: a mismatch fails at launch.
- **Output:** `outputDir` is `test-results/e2e` (Playwright empties it at every start; `test-results/` itself holds other tools' output), traces and screenshots on failure only; the HTML report in `playwright-report/` (ignored), never opened by itself. `npx playwright show-report`; `npx playwright show-trace test-results/e2e/<test>/trace.zip`.
- **Data:** one server for the whole run and parallel workers, so every test makes what it needs through GraphQL (`support/app.ts`: `signIn` through `page.request`, which shares the context's cookies; `graphql`, which fails on an error; `addVehicle`) and never asserts a count or relies on another test's data. No Seeder.
- **Waits are on what the page shows:** the `h1` and no loading message (`pageLoaded`), the selected tab, `MuiCollapse-entered`, `expect.poll`. Never `waitForLoadState('networkidle')` (two settings tabs never reach it) and never a fixed timeout. `retries: 0`: a flaky test is fixed. Click inside the page (`evaluate(el => el.click())`) where a broken layout could cover the target, so the test fails with its layout lines rather than a timeout.
- **The layout check** (`support/layout.ts`, `layoutProblems` / `expectSoundLayout`, which polls until it holds): the document no wider than the viewport; no `dd` value past its panel; no help button over its value; on a coarse pointer every button, `role=button`, `role=tab` and icon link 44 × 44 and every text link 44 px tall (frontend rules, "Touch targets"), with half a pixel of slack (the phone's 2.625 device pixels per CSS pixel), except a link inline in a sentence (its parent has text of its own) and whatever is out of sight (the skip link); a stretched link counts by the box its `::after` covers. It returns readable lines (`"OIDC client id": value ends 235px past its panel`, `touch target 75x26: Tankstat`). Measure before a full-page screenshot: under phone emulation it drops the touch emulation.
- **What runs:** `pages.e2e.ts` (Home with a vehicle card, Overview, Backups, Account, People) and `settings.e2e.ts` (every tab of the Server settings page by its `?tab=` name, which must be the selected tab, since the page falls back to the first one, every section open), each at both sizes. A new page or a page that changed gets its test here.
- **CI:** the `e2e` job in `ci.yml` (`.claude/rules/ci-and-tests.md`).
